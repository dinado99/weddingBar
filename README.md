# 🍶 술 찬장 청첩장 (bar)

술을 좋아하는 부부를 위한 컨셉입니다. 하객이 축하 메시지와 함께 술 한 병을 올리면 찬장이 차곡차곡 채워집니다.

## Supabase로 정식 운영하기 (추천)

하객은 **로그인 없이** 카카오톡 링크로 들어와 술을 올릴 수 있고, 신랑·신부는 이메일 로그인으로 청첩장을 만들고 관리합니다. 한 사이트에서 여러 커플이 각자 청첩장을 만들 수 있습니다.

### 처음 한 번 설정하기

1. **Supabase 프로젝트 만들기**: https://supabase.com 가입 → New project (무료 요금제면 충분합니다. 지역은 Seoul 추천)
2. **표 만들기**: 대시보드 → SQL Editor → `supabase/schema.sql` 내용을 붙여 넣고 Run
3. **하객 익명 로그인 켜기**: Authentication → Sign In / Providers → **Allow anonymous sign-ins** 켜기
4. **로그인 메일이 돌아올 주소 등록**: Authentication → URL Configuration
   - Site URL: `https://wlsdk7245.github.io/weddingBar/`
   - Redirect URLs: 같은 주소 추가
5. **연결 정보 넣기**: Project Settings → API 에서 Project URL 과 anon public 키를 복사해 `config.js` 에 넣기
   (anon 키는 공개되어도 괜찮은 키입니다. 데이터는 아래 권한 규칙이 지킵니다.)
6. **GitHub Pages 켜기**: 배포용 저장소 [`wlsdk7245/weddingBar`](https://github.com/wlsdk7245/weddingBar) 의 Settings → Pages → **Deploy from a branch** → `main` / `/ (root)`.
   이후 `main`에 올라온 내용이 그대로 사이트가 됩니다. (사이트 주소: https://wlsdk7245.github.io/weddingBar/)

### 나중에 추가한 칸 (예전에 SQL을 실행했다면)

SQL Editor에서 아래 두 줄을 실행하세요. 안 하면 청첩장은 저장되지만 배경음악과 국내/해외 구분은 저장되지 않습니다.

```sql
alter table public.invitations add column if not exists bgm text check (char_length(bgm) <= 20);
alter table public.invitations add column if not exists region text not null default 'domestic' check (region in ('domestic','overseas'));
```

### 쓰는 흐름

1. 신랑·신부가 사이트 주소로 들어가 이메일을 넣으면 로그인 링크가 메일로 옵니다.
2. 링크를 누르고 돌아와 **새 청첩장 만들기** → 저장하면 청첩장 주소(`...?i=<청첩장 id>`)로 이동합니다.
3. 청첩장 화면의 **📮 하객에게 보낼 링크**를 복사해 카카오톡으로 보냅니다.
4. 하객은 링크로 들어와 술을 올립니다. 이때 자동으로 익명 로그인되어, 같은 기기에서는 자기 술을 다시 꾸밀 수 있습니다.

### 권한 규칙 (supabase/schema.sql)

| 표 | 읽기 | 쓰기 |
|---|---|---|
| `invitations` 청첩장 | 누구나 | 이메일로 로그인한 사람만 만들기, 주인만 고치기·지우기 |
| `entries` 술병 | 누구나 (숨긴 술병은 주인과 쓴 사람만) | 하객은 청첩장마다 한 병, 자기 것만 고치기 |
| `cheers` 건배 | 누구나 | 자기 건배 횟수만 |

청첩장을 지우면 그 청첩장의 술과 건배도 함께 지워집니다.

### 알아 둘 점

- 하객이 브라우저 데이터를 지우거나 다른 기기로 들어오면, 새 하객으로 인식되어 술을 한 병 더 올릴 수 있습니다.
- 숙성 메시지는 화면에서만 잠깁니다. 데이터는 개봉일 전에도 서버에서 읽을 수 있습니다.
- Supabase 무료 요금제의 기본 메일 발송은 시간당 몇 통으로 제한됩니다. 커플이 많아지면 SMTP 설정이 필요합니다.
- 무료 프로젝트는 일주일 동안 아무도 쓰지 않으면 일시 정지됩니다. 대시보드에서 다시 켤 수 있습니다.

## claude.ai 아티팩트 링크로 열기

👉 https://claude.ai/artifact/Unji3XqE8itzi8j6WgMD6n

claude.ai 아티팩트로 올려 두었고, 아티팩트에 들어 있는 **공유 DB**를 서버로 씁니다. 하객이 올린 술이 모든 사람에게 실시간으로 보입니다.

- **처음 열면** 신랑·신부(아티팩트 주인)에게는 청첩장 만들기 화면이 나옵니다. 저장하면 바로 술장이 열립니다.
- **하객**은 술을 한 사람당 한 병 올릴 수 있고, 다시 올리면 자기 술이 고쳐집니다.
- **관리**: 아티팩트 편집 권한이 있는 사람에게만 "신랑·신부 관리" 버튼이 보입니다. 술병 숨기기, 청첩장 정보 고치기, 전체 지우기를 할 수 있습니다.

### DB 구조와 권한

| 경로 | 내용 | 쓰기 권한 |
|---|---|---|
| `invite/main` | 청첩장 정보, 숨긴 술병 목록 | 신랑·신부(편집 권한자)만 |
| `entries/<하객 id>` | 하객 한 명의 술 한 병 | 본인만 (참여 권한 이상) |
| `cheers/<하객 id>` | 하객별 건배 횟수 | 본인만 (참여 권한 이상) |

### 하객 공유 시 주의

- 하객도 **claude.ai 계정으로 로그인**해야 보고 참여할 수 있습니다. 로그인하지 않으면 DB를 읽을 수 없습니다.
- 술을 **올리려면** 하객에게 쓰기 권한이 있어야 합니다. 개인 요금제에서는 공유 메뉴에서 하객을 이메일로 **편집자**로 초대해야 하고, 공개 링크로 공유하면 하객은 보기만 할 수 있습니다. 팀 요금제에서는 **참여자(Contributor)** 권한이면 됩니다.
- 숙성 메시지는 화면에서만 잠기고, DB에는 그대로 저장됩니다. 비밀 편지로 쓰기에는 아직 부족합니다.

## 직접 실행하기 (서버 없이)

`config.js` 를 비워 둔 채 `index.html`을 브라우저로 열면 됩니다. 이때는 데이터가 그 브라우저(localStorage)에만 저장됩니다.
"예시 화면 먼저 둘러보기"를 누르면 저장되지 않는 예시 데이터로 볼 수 있습니다.

## 아티팩트 다시 올리기

```
python3 build_artifact.py <출력 파일.html>
```
CSS, JS, 폰트를 한 파일에 넣은 HTML이 만들어집니다. 이 파일을 같은 아티팩트 주소로 다시 올리면 됩니다.

## 들어 있는 기능

| 기능 | 설명 |
|---|---|
| 청첩장 만들기 | 신랑·신부 이름, 날짜·시간, 장소, 계좌, 인사말, 좋아하는 술 |
| 술 찬장 | 첫 칸에 신랑·신부의 술(리본)이 놓이고, 하객 술이 이어서 쌓임. 하객이 늘면 선반이 늘어남 |
| 술 올리기 | 8종(소주·맥주·막걸리·와인·샴페인·위스키·사케·칵테일), 병 색깔, 리본, 신랑측/신부측, 메시지 |
| 메시지 보기 | 술병을 누르면 병이 흔들리며 "뽁" 소리와 함께 메시지가 한 글자씩 나옴 |
| 숙성 메시지 | 밀랍으로 봉인되고 결혼 1주년에 열림 |
| 건배 버튼 | 잔 부딪히는 효과음과 건배 횟수 |
| 배경음악 | 청첩장 만들 때 8비트로 편곡한 클래식 10곡 중 하나를 고름. 하객이 화면을 처음 만지면 재생되고, 오른쪽 위 버튼으로 끄고 켬 |
| 술 취향 통계 | 어떤 술이 몇 병 올라왔는지 막대그래프로 표시 |
| 예식 안내 | 일시, 장소, 계좌번호 복사. 지도는 국내면 네이버 지도·카카오맵, 해외면 구글 지도 |
| 관리 | 편집 권한자만: 술병 숨기기/보이기, 청첩장 정보 고치기, 전체 지우기 |

## 파일 구성

```
bar/
├── index.html   화면 구조
├── style.css    픽셀 스타일
├── sprites.js   술병 픽셀아트 (문자 격자로 그림, 이미지 파일 없음)
├── music.js     8비트 배경음악 10곡과 재생기 (음원 파일 없음)
├── config.js    Supabase 연결 정보 (비우면 서버 없이 동작)
├── store.js     데이터 저장 (Supabase / 아티팩트 공유 DB / 브라우저 localStorage / 예시)
├── supabase/schema.sql  Supabase 표와 권한 규칙
├── app.js       찬장 그리기, 술 올리기, 메시지 보기, 관리 기능
├── build_artifact.py  아티팩트용 한 파일 HTML 만들기
└── fonts/       Galmuri11 픽셀 폰트 (SIL OFL 라이선스, OFL-Galmuri.txt 참고)
```
